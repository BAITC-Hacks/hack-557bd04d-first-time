# Протокол совещаний с фиксацией поручений

HackAlem AI 2026, трек 08 «Инновации» — система автопротоколирования совещаний
с фиксацией поручений. Команда **First time**.

## Что решаем

Протоколы совещаний ведут вручную: это долго, а поручения, сроки и ответственные
теряются или искажаются. Система принимает запись совещания и возвращает протокол —
краткую сводку, список решений и **поручения с ответственным, сроком и приоритетом**,
с выгрузкой в DOCX.

Ключевое отличие от простого пересказа — **проверяемость**. Каждое поручение
привязано к точной цитате из стенограммы и таймкоду: клик по карточке подсвечивает
момент, где это прозвучало. Цитату проверяет код, а не модель — если дословный
фрагмент не найден в стенограмме, поручение помечается неподтверждённым и его
уверенность снижается. Ответственный и срок, которых не было в разговоре, не
выдумываются: поле остаётся пустым. Решение принимает человек — каждое поручение
подтверждается или отклоняется.

## Соответствие обязательному минимуму

| # | Требование задания | Как закрыто |
|---|---|---|
| 1 | Распознавание речи участников | Vosk локально, `meeting/stt_local.py` |
| 2 | Понимание русского языка | модель `vosk-model-ru`, проверено на записях задания |
| 3 | Понимание казахского языка | модель `vosk-model-kz` (WER 4.49 на корпусе KSC) |
| 4 | Понимание шала-казахского | обе модели запускаются на записи, побеждает та, у которой выше уверенность распознавания |
| 5 | Поручения с ответственным и сроком | `meeting/pipeline.py`, извлечение + проверка цитат |
| 6 | Диаризация с привязкой к человеку | локально: векторы голоса Vosk + кластеризация, `_assign_speakers` |
| 7 | Экспорт протокола в файл | DOCX, `meeting/export_docx.py`, кнопка «Скачать DOCX» |

**Про пункт 4.** Язык заранее не угадываем: совещания в Казахстане — это чаще всего
смесь русского и казахского. Прогоняем запись обеими локальными моделями и берём ту,
где средняя уверенность распознавания выше; выбор и обе оценки видны в ответе API.
На приложенных к заданию записях выигрывает русская модель (0.913 против 0.897),
на казахской речи — казахская. Это честный компромисс: отдельной модели для
смешанной речи в открытом доступе нет, а угадывание языка заранее даёт худший
результат, чем выбор по факту.

## Закрытый контур и приватность

Задание запрещает передавать аудио во внешние облачные API и требует возможности
развернуть решение у заказчика.

- **Распознавание речи и различение говорящих работают полностью локально.**
  Модели Vosk (Apache 2.0) лежат в `models/`, аудио не покидает машину.
  Интернет для этой части не нужен вообще.
- **Разбор текста** в прототипе выполняет Claude. Провайдер разбора вынесен за
  интерфейс `extract()`: для закрытого контура на его место становится локальная
  LLM без изменений остального кода. В текущей версии локальный разбор не
  реализован — это честное ограничение прототипа, а не скрытая зависимость.
- Загруженный файл живёт во временном файле и удаляется сразу после разбора.
  Результаты лежат в `storage/` и не версионируются. Ключи — только в `.env`.

## Архитектура

```
запись (аудио или видео, любой формат)
      │  ffmpeg -> WAV 16 кГц моно
      ▼
[ Vosk, локально ]  две модели: русская и казахская
      │             выбираем по уверенности распознавания
      │             + векторы голоса -> кластеризация -> говорящие
      ▼  сегменты: время + говорящий + текст
[ разбор совещания ]  протокол, решения, поручения
      │  JSON: speakers + what / who / due / priority / quote / confidence
      ▼
[ проверка ]  цитата ищется в стенограмме, таймкод берётся из неё,
      │       а не из ответа модели; имя говорящего принимается,
      │       только если оно прозвучало в записи
      ▼
[ веб-интерфейс ]  карточки поручений ↔ стенограмма, подтверждение
      │            человеком, именование говорящих, экспорт DOCX
      ▼
storage/meetings/<id>.json
```

## Технологии

| Слой | Чем сделано |
|---|---|
| Бэкенд | Python 3.8+, стандартная библиотека (`http.server`) |
| Распознавание речи | **Vosk**, локально: `vosk-model-ru`, `vosk-model-kz` |
| Различение говорящих | **Vosk x-vectors** + кластеризация по косинусной близости, локально |
| Аудио и видео | ffmpeg из пакета `imageio-ffmpeg` — отдельная установка не нужна |
| Разбор совещания | Anthropic Claude `claude-opus-5` |
| Экспорт | DOCX собирается стандартной библиотекой, без внешних пакетов |
| Интерфейс | один HTML-файл без сборки и фреймворков |
| Хранилище | JSON-файлы в `storage/meetings/` |

## Установка

Нужен Python 3.8 или новее.

```bash
pip install -r requirements.txt
python scripts/get_models.py
```

Второй шаг скачивает локальные модели (~180 МБ) в `models/`.

**Качество распознавания напрямую зависит от размера модели.** Компактные модели
уверенно справляются с чистой записью — на приложенных к заданию совещаниях они
дают связную стенограмму. На записи с телефона в шумном помещении их не хватает.
Для таких условий ставьте большие модели:

```bash
python scripts/get_models.py --full
```

Это ещё около 3 ГБ (`vosk-model-ru-0.42` и `vosk-model-kz-0.42`), зато заметно
точнее. Скрипт сам предпочитает большую модель, если она есть.

Замеры на нашей тестовой записи (телефон, шумное помещение, три говорящих):

| Модель | Средняя уверенность | Распознано говорящих |
|---|---|---|
| `vosk-model-small-ru-0.22`, 88 МБ | 0.860 | 1 |
| `vosk-model-ru-0.42`, 3 ГБ | **0.924** | **4** |

На чистой записи из задания хватает и компактной модели — там она даёт 0.913.
Разница проявляется именно на сложном звуке, и на нём же ломается диаризация:
маленькая модель сваливает всех участников в одного говорящего.

Для разбора совещания скопируйте `.env.example` в `.env` и укажите ключ:

| Переменная | Назначение | Без неё |
|---|---|---|
| `ANTHROPIC_API_KEY` | разбор совещания | демо-режим на готовом разборе |
| `STT_PROVIDER` | `local` (по умолчанию) или `soniox` | локальное распознавание |
| `SONIOX_API_KEY` | только если явно выбран `soniox` | не используется |
| `ANALYSIS_MODEL` | модель разбора, по умолчанию `claude-opus-5` | — |
| `SPEAKER_THRESHOLD` | порог схожести голосов, по умолчанию `0.62` | — |
| `PORT` | порт сервера, по умолчанию `8000` | — |

## Запуск

```bash
python app.py
```

Откройте <http://localhost:8000>. В шапке видно, какие режимы активны.

## Проверка основного сценария за 2 минуты

**Ключи не нужны** — проект проверяется полностью в демо-режиме.

1. `python app.py` — в консоли появятся текущие режимы работы.
2. Откройте <http://localhost:8000> и нажмите **«Разобрать пример»**.
3. Ожидаемый результат: протокол планёрки, 3 решения и **4 поручения**:
   - Айдана — макет экрана оплаты, срок «четверг», уверенность 95%;
   - Тимур — таймаут выгрузки отчётов, срок «среда», уверенность 93%;
   - Марат — список клиентов для пилота, срок «пятница», уверенность 90%;
   - без ответственного — посмотреть логи, срок не назван, уверенность 45%.
4. Нажмите на карточку поручения — в стенограмме справа подсветится момент,
   из которого оно извлечено.
5. Нажмите **«Подтвердить»** — статус сохраняется в `storage/meetings/<id>.json`.
6. Нажмите **«Скачать DOCX»** — протокол выгружается файлом.

Четвёртое поручение показывает поведение при неопределённости: прозвучало
«надо бы посмотреть логи», ответственный и срок названы не были — система не
выдумывает их, а помечает низкой уверенностью.

**Проверка на своей записи.** Нажмите «Загрузить запись…» и выберите аудио- или
видеофайл. Распознавание пойдёт локально; для разбора нужен `ANTHROPIC_API_KEY`.
Запись на 4,5 минуты проходит весь путь примерно за полторы минуты.

Проверка через API без браузера:

```bash
curl -s http://localhost:8000/api/health
curl -s -X POST http://localhost:8000/api/analyze -H "Content-Type: application/json" -d "{}"
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | статус и текущие режимы работы |
| `POST` | `/api/analyze` | `{}` — демо-пример; `{filename, audio_b64, title}` — своя запись |
| `GET` | `/api/meetings` | список разобранных совещаний |
| `GET` | `/api/meetings/<id>` | одно совещание целиком |
| `GET` | `/api/meetings/<id>/export.docx` | протокол файлом DOCX |
| `POST` | `/api/meetings/<id>/items/<item_id>` | `{"status": "confirmed"\|"rejected"\|"pending"}` |
| `POST` | `/api/meetings/<id>/speakers` | `{"from": "Спикер 1", "to": "Марат"}` — дать имя говорящему |

## Сторонние и заранее подготовленные компоненты

В соответствии с пунктами 5.4.4 и 5.4.4.2 Положения:

- **Модели:** Vosk `vosk-model-ru`, `vosk-model-kz`, `vosk-model-spk` — Apache 2.0,
  работают локально.
- **Библиотеки:** `vosk` (Apache 2.0), `imageio-ffmpeg` (BSD, включает ffmpeg под LGPL),
  `anthropic` (MIT). Остальное — стандартная библиотека Python.
- **Внешние сервисы:** Anthropic Claude для разбора текста. Soniox — опциональный
  провайдер распознавания, по умолчанию выключен.
- **Заранее подготовленное:** у команды есть личный проект расшифровки аудио, из
  опыта которого взяты подходы к работе с распознаванием речи и к деградации на
  заглушки при недоступности внешнего сервиса. Доменная логика этого проекта —
  протокол совещания, поручения с ответственным и сроком, проверка цитат,
  восстановление имён говорящих, подтверждение человеком, экспорт — разработана
  в рамках соревновательной части хакатона.
- **AI-инструменты:** разработка велась с использованием AI-ассистентов, что
  разрешено пунктом 5.4.12 Положения.
