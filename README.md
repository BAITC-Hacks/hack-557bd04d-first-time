# Протокол совещаний с фиксацией поручений

HackAlem AI 2026, трек 08 «Инновации» — система автопротоколирования совещаний
с фиксацией поручений. Команда **First time**.

## Что решаем

После совещания договорённости теряются: кто-то не записал, кто-то понял иначе,
через неделю никто не помнит, кто отвечал за задачу и к какому сроку.

Система принимает запись совещания и возвращает протокол: краткую сводку, список
решений и **поручения с ответственным, сроком и приоритетом**.

Ключевое отличие от простого пересказа — **проверяемость**. Каждое поручение
привязано к точной цитате из стенограммы и таймкоду: клик по карточке
подсвечивает момент, где это прозвучало. Цитату проверяет код, а не модель —
если дословный фрагмент не найден в стенограмме, поручение помечается как
неподтверждённое и его уверенность снижается. Ответственный и срок, которых не
было в разговоре, не выдумываются: поле остаётся пустым.

Решение принимает человек: каждое поручение подтверждается или отклоняется.

## Архитектура

```
запись (wav/mp3)
      │
      ▼
[ Soniox stt-async-v5 ]  распознавание речи, ru/kk, разделение говорящих
      │  сегменты: время + говорящий + текст
      ▼
[ Claude claude-opus-5 ]  извлечение протокола, решений и поручений
      │  JSON: what / who / due / priority / quote / confidence
      ▼
[ проверка цитат ]  цитата ищется в стенограмме, таймкод берётся из неё,
      │             а не из ответа модели
      ▼
[ веб-интерфейс ]  карточки поручений ↔ стенограмма, подтверждение, экспорт
      │
      ▼
storage/meetings/<id>.json
```

Оба внешних сервиса имеют демо-замену: без ключей проект работает на готовом
примере из `samples/` и остаётся полностью проверяемым.

## Технологии

| Слой | Чем сделано |
|---|---|
| Бэкенд | Python 3.8+, только стандартная библиотека (`http.server`) |
| Распознавание речи | Soniox `stt-async-v5`, подсказки языков `ru,kk` |
| Разбор совещания | Anthropic Claude `claude-opus-5`, официальный SDK `anthropic` |
| Интерфейс | Один HTML-файл без сборки и без фреймворков |
| Хранилище | JSON-файлы в `storage/meetings/` |

Зависимость ровно одна — пакет `anthropic`, и только для боевого режима.

## Установка

Нужен Python 3.8 или новее.

```bash
pip install -r requirements.txt
```

Для боевого режима скопируйте `.env.example` в `.env` и заполните ключи:

```bash
cp .env.example .env
```

| Переменная | Назначение | Без неё |
|---|---|---|
| `ANTHROPIC_API_KEY` | разбор совещания | демо-режим на готовом разборе |
| `SONIOX_API_KEY` | распознавание речи | демо-режим на готовой стенограмме |
| `ANALYSIS_MODEL` | модель разбора, по умолчанию `claude-opus-5` | — |
| `SONIOX_MODEL` | модель распознавания, по умолчанию `stt-async-v5` | — |
| `SONIOX_LANGUAGE_HINTS` | языки, по умолчанию `ru,kk` | — |
| `PORT` | порт сервера, по умолчанию `8000` | — |

## Запуск

```bash
python app.py
```

Откройте <http://localhost:8000>.

## Проверка основного сценария за 2 минуты

**Ключи не нужны** — проект проверяется полностью в демо-режиме.

1. `python app.py` — в консоли появится строка с режимами работы.
2. Откройте <http://localhost:8000> и нажмите **«Разобрать пример»**.
3. Ожидаемый результат: протокол планёрки, 3 решения и **4 поручения**:
   - Айдана — макет экрана оплаты, срок «четверг», уверенность 95%;
   - Тимур — таймаут выгрузки отчётов, срок «среда», уверенность 93%;
   - Марат — список клиентов для пилота, срок «пятница», уверенность 90%;
   - без ответственного — посмотреть логи, срок не назван, уверенность 45%.
4. Нажмите на любую карточку поручения — в стенограмме справа подсветится момент,
   из которого оно извлечено.
5. Нажмите **«Подтвердить»** — карточка меняет статус, он сохраняется в
   `storage/meetings/<id>.json`.

Четвёртое поручение показывает поведение при неопределённости: в разговоре
прозвучало «надо бы посмотреть логи», ответственный и срок названы не были —
система не выдумывает их, а честно помечает низкой уверенностью.

Проверка через API без браузера:

```bash
curl -s http://localhost:8000/api/health
curl -s -X POST http://localhost:8000/api/analyze -H "Content-Type: application/json" -d "{}"
```

Для боевого режима нажмите **«Загрузить запись…»** и выберите аудиофайл.

## API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | статус и текущие режимы работы |
| `POST` | `/api/analyze` | `{}` — демо-пример; `{filename, audio_b64, title}` — своя запись |
| `GET` | `/api/meetings` | список разобранных совещаний |
| `GET` | `/api/meetings/<id>` | одно совещание целиком |
| `POST` | `/api/meetings/<id>/items/<item_id>` | `{"status": "confirmed"\|"rejected"\|"pending"}` |

## Структура проекта

```

web/index.html               интерфейс
samples/planerka.json        демо-стенограмма
samples/planerka.analysis.json  демо-разбор для работы без ключей
```

## Сторонние и заранее подготовленные компоненты

В соответствии с пунктами 5.4.4 и 5.4.4.2 Положения:

- **Внешние сервисы:** Soniox (распознавание речи), Anthropic Claude (разбор).
  Используются по их публичным API, ключи в репозиторий не попадают.
- **Библиотеки:** `anthropic` (MIT). Остальное — стандартная библиотека Python.
- **Заранее подготовленное:** у команды есть личный проект расшифровки аудио,
  из опыта которого взяты подходы к работе с Soniox и к деградации на заглушки
  при недоступности внешнего сервиса. Доменная логика этого проекта (протокол
  совещания, поручения с ответственным и сроком, проверка цитат, подтверждение
  человеком) разработана в рамках соревновательной части хакатона.
- **AI-инструменты:** разработка велась с использованием AI-ассистентов,
  что разрешено пунктом 5.4.12 Положения.

## Данные

Демо-запись `samples/planerka.json` — постановочная, составлена командой.
Персональных данных и записей реальных людей проект не содержит.
Загруженные аудиофайлы обрабатываются локально и во временном файле, который
удаляется сразу после разбора; результаты лежат в `storage/` и не версионируются.
